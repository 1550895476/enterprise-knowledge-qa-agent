# 复盘与下一步

## 最难的问题

最难的是区分“检索到了候选”与“原文足以支持答案”。如果直接使用摘要，冲突制度很容易被错误地压成一个数字。因此当前实现要求先读取原文，再做冲突判断，并把适用范围、版本日期和原文一起返回。

另一个难点是让离线示例仍然符合动态决策要求。解决办法是把决策放进独立模型接口，工具观察作为下一次模型输入；离线模型只是可复现的替身，线上可替换成真实模型。

## 学习收获

- Agent 的关键不在框架名称，而在状态、工具观察和停止条件是否可审计；
- 引用必须来自实际读取的内容，不能只引用搜索标题；
- 失败路径和资料不足应成为一等输出，而不是异常日志里的隐含信息。

## 下一步

1. 用 embedding/BM25 替换词项检索，并保留原文证据门槛；
2. 让文档解析器抽取主题、数值、适用范围和生效/失效日期，支持更复杂冲突；
3. 增加离线评测集和模型版本对比，统计引用准确率、冲突召回率和无依据回答率；
4. 在接入真实企业知识库前增加权限过滤、审计日志和敏感信息脱敏。
